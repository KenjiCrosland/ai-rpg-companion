## 01 Thornback — CR 5, "an ankheg but legendary, boss fight for level 5"  ✅ FIXED

```
Bite. Melee Attack Roll: +6 (with Advantage if the target is Grappled by Thornback),
      reach 5 ft. 12 (2d8 + 3) Piercing damage plus 3 (1d6) Acid damage.
      If the target is a Large or smaller creature, it has the Grappled condition (escape DC 14).
```

Was, on typed40 #33: `(with Advantage if the target is Grappled by the ankheg)`.

Print's own Ankheg Bite writes that noun. The parenthetical is `pr.note`, and it was the one
print-text paste of the group that never ran `asInline`.

**The part worth keeping:** the audit caught this and the engine let it go.

```
audit finding on print: Actions/"Bite" — The Bite rider refers to a different creature
  (the ankheg) than the block's own Thornback. print's row is the standard, so this is
  either the audit arguing with published text or OUR paste having broken it; no fix runs
```

It was our paste. The print stamp means "carries print's name", not "is print's text" — the
exemption hole already on the open list, now with a concrete sheet behind it.

## 02 Rimebound Troll — CR 6, "a troll caked in black ice that hauls prey into the drifts"  ✅ FIXED

```
Charge. The rimebound troll moves up to half its Speed straight toward an enemy it can see.
```

Was, on typed40 #31: `The target is pulled up to 10 feet straight toward Troll`.

`personalName` reads "Rimebound Troll" as an epithet plus a GIVEN name (the Ashvowed-Brannor
rule) and answers **"Troll"** — a kind, not a person. Correcting that rule means widening
`ROLE_NOUN`, which is not ours to do. The fix is that nothing downstream is told the guess:
the seat call and the repair call now get the settled name.

The chain on the original sheet, from its own trace:

```
138  seat authored the row: … "Frozen Gristle Hurl" -> Actions. … straight tow[ard Troll]
173  audit: … Frozen Gristle Hurl: Refers to the creature as 'Tr…
179  row repair: "Frozen Gristle Hurl" [free row] — the audit faults it … re-authored
 73  Frozen Gristle Hurl. … pulled up to 10 feet straight toward Troll   << still wrong
```

The audit caught it, ordered a repair, and the repair was handed the same wrong name and wrote
it back. Both calls run ~1,600 lines after the name is settled.

**Caveat, stated plainly:** this roll dropped its signature row, so the seat-authored path was
not exercised. What the block proves is that the sheet no longer carries the guess; the seat
fix's direct evidence is the traced chain above, not this card.

## 03 Lord Vexmoor — CR 12, "an archmage in a black doublet…"  ❌ at the time; ✅ FIXED 17:17

```
Spellcasting.          Vexmoor casts one of the following spells, using Intelligence…
Protective Magic (3/Day). Trigger: Vexmoor is hit by an attack roll. Response: Vexmoor casts Shield…
Misty Step (3/Day).    The mage casts Misty Step, using the same spellcasting ability as Spellcasting.
```

Two of the three rows take Vexmoor's name. The third does not, and **this one is not an engine
bug.** Print's own Archmage block writes itself two different ways:

```
Archmage -> self-reference nouns: archmage x4,  mage x1
Archmage | Bonus Actions | Misty Step (3/Day) :: "The mage casts *Misty Step*…"
```

`asInline` substitutes the nouns of the body's NAME. `mage` is not a word of `Archmage` — it is
a trailing substring of one — so no amount of source-passing catches it. Catching it needs a
rule about print's text, which is the owner's call. **Not written.** The owner ruled on
2026-11-14 that the DATA is repaired instead — see `BLOCKS-archmage-2026-11-14.md`, where the
re-run reads "Misty Step (3/Day). Lord Vexmoor casts Misty Step".

And again:

```
audit finding on print: Bonus Actions/"Misty Step" — The entry refers to the creature as
  'the mage', a name not used anywhere else on the sheet. print's row is the standard … no fix runs
```
