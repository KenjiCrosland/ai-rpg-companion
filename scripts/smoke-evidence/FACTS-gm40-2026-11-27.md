## 1. Which function turned "Assassin Vine" into the Assassin, and by what rule

**Corrected, 27 November.** I first named `printCanonFor` and its head-word match. That was wrong:
`printCanonFor("Assassin Vine", cr)` returns null at every CR, and I confirmed it by replaying s26
with a guard on that lookup — the sheet was still the Assassin.

The function is **`corpusEntry` in `path.mjs`**, called where the path call's answer is normalised,
and the rule is its **variant rule**, which the code states as "the longest corpus name the answer
contains as whole words — tail or head". It was added on 19 October so that "Cave Troll" resolves to
the Troll and "Stone Giant Exile" to the Stone Giant. "Assassin Vine" contains "Assassin" as whole
words, so the Assassin is returned.

**Confirmed from the code, as asked.** And Fable's follow-up is right: the rule I proposed in his
section 8 — the entry's name must hold every word the call named — would refuse "Cave Troll" and
undo that fix. It is not built here or anywhere. What separates the two cases is the creature's
type: a cave troll is a Giant like the Troll, an assassin vine is a Plant and the Assassin is a
Humanoid. That check needs a type with the GM's words behind it, so **A4 moves to Part C** and s26
stays the Assassin for this round.
