# Plans

Forward-dated implementation notes for work that isn't being done now but will need to be done when a specific feature lands. Each file describes:

- The trigger — the feature or change that makes the plan relevant.
- The problem the plan exists to solve.
- The recommended approach, with enough detail that a future session can act on it without rebuilding context.

If you (Claude) are about to start work that touches a domain in this folder, **read the relevant plan first**. Plans are written assuming you have no memory of the conversations that produced them.

## When to add a plan here

- A latent issue exists that's harmless today but will bite once a specific feature ships.
- A design decision was made but deferred — the rationale needs to survive past the conversation.
- A workaround was chosen with the explicit understanding that it gets revisited later.

Don't use this folder for general roadmap items, ideas, or task lists. Plans here are about preserving *technical context that would otherwise be lost*.

**Critical harness fix (2026-06-24):** `seedStorage` is now **one-shot per key** (sessionStorage guard). It used `addInitScript`, which re-runs on every reload — so any test that mutated state then reloaded (`switchTool`/`page.reload`) had its mutation silently clobbered by a re-seed of the original value. This was masking real app behavior; the propagation tests only became valid after the fix. Any new reload-based test depends on it.

**Cross-tool propagation coverage** (`tests/cross-tool/propagation-*.spec.js`, `links.spec.js`): item↔NPC rename/delete + statblock-delete (earlier); NPC rename → name fans out to item/setting/dungeon stubs (`renameNPCReferences`); dungeon rename → item stub + dungeon-sourced NPC label; and the cross-tool "View in X" / NPC source links navigate to the right tool with the entity selected (dev params are sessionStorage, so the destination is asserted, not the URL).

**Production bug fixed (2026-06-24):** there was no `renameDungeonReferences` — renaming a dungeon left dungeon-sourced NPC labels (and other denormalized name caches) stale (settings already propagated this). Added `renameDungeonReferences` to `dungeon-storage.mjs` (items' related_dungeons stubs, tool-references, dungeon-sourced NPC `sourceName`+`typeOfPlace`) and wired it into the dungeon overview saveEdit. Tested.

Production changes across the whole expansion: `data-testid` additions, the `confirm()`→`ParConfirm` migration, and the `renameDungeonReferences` fix. Everything else is test + fixtures.
